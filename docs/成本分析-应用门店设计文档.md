# 成本分析 - 应用门店模块设计文档

## 📋 模块概述

"应用门店"模块用于配置哪些门店启用成本分析功能。管理员可以从在营门店列表中选择门店，并为其启用或停用成本分析。

## 🎯 业务逻辑

### 核心概念
- **在营门店**：所有正常营业的门店（`is_active = true`）
- **应用门店**：在营门店中启用了成本分析的门店（`cost_analysis_enabled = true`）
- **停用**：临时关闭某个门店的成本分析功能，不删除门店数据

### 业务流程
1. 管理员添加门店到系统（可以同时启用成本分析）
2. 系统自动标记门店为"在营"状态
3. 管理员可以随时启用/停用门店的成本分析功能
4. 启用后，该门店的订单将参与成本分析计算
5. 停用后，该门店的订单不再参与成本分析（但数据保留）

## 🗄️ 数据库设计

### 表结构：`eleme_active_stores`

复用现有的在营门店表，添加成本分析标记字段：

```sql
CREATE TABLE `eleme_active_stores` (
  `id` int NOT NULL AUTO_INCREMENT PRIMARY KEY,
  `store_name` varchar(200) NOT NULL UNIQUE COMMENT '门店名称（饿了么）',
  `store_name_shiheng` varchar(200) DEFAULT NULL COMMENT '门店名称（食亨）',
  `is_active` tinyint(1) DEFAULT 1 COMMENT '是否在营',
  `cost_analysis_enabled` tinyint(1) DEFAULT 0 COMMENT '是否启用成本分析',
  `created_at` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  KEY `idx_store_name` (`store_name`),
  KEY `idx_cost_analysis` (`cost_analysis_enabled`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 字段说明

| 字段 | 类型 | 说明 | 默认值 |
|------|------|------|--------|
| id | int | 主键ID | 自增 |
| store_name | varchar(200) | 门店名称（饿了么），唯一 | 必填 |
| store_name_shiheng | varchar(200) | 门店名称（食亨） | NULL |
| is_active | boolean | 是否在营 | true |
| cost_analysis_enabled | boolean | 是否启用成本分析 | false |
| created_at | datetime | 创建时间 | 当前时间 |
| updated_at | datetime | 更新时间 | 当前时间 |

## 🔌 后端API设计

### API端点列表

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/api/cost-analysis/applied-stores` | 获取应用门店列表 |
| POST | `/api/cost-analysis/applied-stores` | 创建新的应用门店 |
| PUT | `/api/cost-analysis/applied-stores/:id` | 更新应用门店信息 |
| PUT | `/api/cost-analysis/applied-stores/:id/toggle` | 切换成本分析启用状态 |
| DELETE | `/api/cost-analysis/applied-stores/:id` | 删除应用门店 |
| GET | `/api/cost-analysis/applied-stores/summary` | 获取统计信息 |

### API详细说明

#### 1. 获取应用门店列表

```http
GET /api/cost-analysis/applied-stores
```

**Query参数：**
- `page`: 页码（默认1）
- `per_page`: 每页数量（默认10）
- `search`: 搜索关键词（门店名称）
- `enabled_only`: 是否只显示已启用的门店（默认false）

**Response：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "stores": [
      {
        "id": 1,
        "store_name": "圣比萨·披萨·意面(温溪店)",
        "store_name_shiheng": "温溪店",
        "is_active": true,
        "cost_analysis_enabled": true,
        "created_at": "2025-10-22T10:00:00",
        "updated_at": "2025-10-22T10:00:00"
      }
    ],
    "total": 58,
    "page": 1,
    "per_page": 10,
    "pages": 6
  }
}
```

#### 2. 创建新的应用门店

```http
POST /api/cost-analysis/applied-stores
```

**Request Body：**
```json
{
  "store_name": "圣比萨·披萨·意面(温溪店)",
  "store_name_shiheng": "温溪店",
  "cost_analysis_enabled": true
}
```

**Response：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "store": { ... },
    "message": "门店创建成功"
  }
}
```

#### 3. 更新应用门店

```http
PUT /api/cost-analysis/applied-stores/:id
```

**Request Body：**
```json
{
  "store_name": "圣比萨·披萨·意面(温溪店)",
  "store_name_shiheng": "温溪店",
  "cost_analysis_enabled": true
}
```

#### 4. 切换成本分析状态

```http
PUT /api/cost-analysis/applied-stores/:id/toggle
```

**Response：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "store": { ... },
    "message": "成本分析已启用/停用"
  }
}
```

#### 5. 删除应用门店

```http
DELETE /api/cost-analysis/applied-stores/:id
```

#### 6. 获取统计信息

```http
GET /api/cost-analysis/applied-stores/summary
```

**Response：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total_stores": 58,
    "enabled_stores": 45,
    "disabled_stores": 13
  }
}
```

## 🎨 前端设计

### 页面结构

```
应用门店标签页
├── 统计信息卡片（3个）
│   ├── 总门店数

        ├── 门店名称（食亨）
        ├── 成本分析状态（Switch开关）
        ├── 创建时间
        ├── 更新时间
        └── 操作（编辑、删除）
```

### 组件文件

- **组件路径**：`admin-web/src/pages/Delivery/Eleme/components/AppliedStoresTab.tsx`
- **API接口**：`admin-web/src/api/costAnalysis.ts`

### 核心功能

1. **列表展示**：分页显示所有在营门店及其成本分析状态
2. **搜索功能**：支持按门店名称搜索
3. **添加门店**：弹窗表单添加新门店
4. **编辑门店**：弹窗表单编辑门店信息
5. **启用/停用**：Switch开关一键切换成本分析状态
6. **删除门店**：二次确认后删除门店
7. **统计信息**：实时显示门店统计数据

### 交互说明

- **Switch开关**：点击立即生效，无需确认
- **删除操作**：需要二次确认，提示数据无法恢复
- **编辑表单**：必填字段验证
- **搜索功能**：支持回车搜索

## 📊 数据流转

```
用户操作 → 前端组件 → API调用 → 后端路由 → 数据库操作 → 返回结果 → 更新界面
```

### 示例：启用成本分析

1. 用户点击Switch开关
2. 前端调用 `toggleCostAnalysis(id)`
3. 发送 `PUT /api/cost-analysis/applied-stores/:id/toggle`
4. 后端更新数据库 `cost_analysis_enabled = !cost_analysis_enabled`
5. 返回更新后的门店数据
6. 前端刷新列表和统计信息

## 🔒 权限控制

所有API端点都需要 `@token_required` 装饰器验证：
- 用户必须登录
- Token有效期内
- 具有相应操作权限

## 📝 注意事项

1. **数据一致性**：在营门店和应用门店使用同一张表，避免数据冗余
2. **软删除**：删除门店时应考虑是否需要软删除以保留历史数据
3. **关联数据**：删除门店前应检查是否有关联的成本数据
4. **并发控制**：Switch开关操作应考虑并发情况
5. **审计日志**：重要操作应记录操作日志
