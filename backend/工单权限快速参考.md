# 工单权限快速参考卡 🎫

## 🎯 核心原则
**一句话总结**：谁创建或被分配，谁就能看到和操作工单

---

## 👥 角色定义

| 角色 | 英文标识 | 权限特点 |
|------|---------|---------|
| **管理员** | `admin` | 上帝视角，看所有工单，但不接收工单 |
| **区域经理** | `regional_manager` | 只看自己相关的工单 |
| **店长** | `shop_manager` | 只看自己相关的工单 |
| **外卖运营** | `eleme_operator` | 只看自己相关的工单 |

---

## 🔍 工单可见性规则

### Admin
```
✅ 所有工单
```

### 其他角色（区域经理/店长/外卖运营）
```
✅ 我创建的工单
✅ 分配给我的工单
❌ 其他人之间的工单
```

## 📝 工单分配矩阵

|  | 可以分配给 ↓ |
|--|-------------|
| **管理员** | 区域经理 ✅ / 店长 ✅ / 外卖运营 ✅ / 管理员 ❌ |
| **区域经理** | 区域经理 ✅ / 店长 ✅ / 外卖运营 ✅ / 管理员 ❌ |
| **店长** | 区域经理 ✅ / 店长 ✅ / 外卖运营 ✅ / 管理员 ❌ |
| **外卖运营** | 区域经理 ✅ / 店长 ✅ / 外卖运营 ✅ / 管理员 ❌ |

**规则**：
- ✅ 可以互相分配工单
- ❌ 不能给管理员分配工单

## 🔄 状态更新权限

| 状态转换 | Admin | 区域经理 | 店长 | 外卖运营 |
|---------|-------|---------|------|---------|
| 待受理 → 进行中 | ✅ | ✅ | ✅ | ✅ |
| 进行中 → 已完成 | ✅ | ✅ | ✅ | ✅ |
| 已完成 → 已归档 | ✅ | ✅ | ✅ | ✅ |
| 其他跳转 | ✅ | ✅ | ✅ | ✅ |

**限制**：
- ⚠️ 只有"已完成"才能转为"已归档"
- ⚠️ 只能修改自己相关的工单（admin除外）

## 🚫 禁止操作

| 操作 | 原因 |
|------|------|
| ❌ 给admin分配工单 | Admin不接收任务，只负责管理 |
| ❌ 查看不相关工单详情 | 返回403错误 |
| ❌ 修改不相关工单 | 返回403错误 |

## 📊 API端点权限总览

### GET /api/work-orders/ (工单列表)
- **Admin**: 所有工单
- **其他**: 自己创建 OR 分配给自己的

### GET /api/work-orders/:id (工单详情)
- **Admin**: 任何工单
- **其他**: 仅自己相关的（否则403）

### POST /api/work-orders/ (创建工单)
- **所有角色**: 都可以创建
- **必填字段**: title, type_id, priority_id, assignee_id
- **验证**: assignee_id不能是admin

### PUT /api/work-orders/:id (更新工单)
- **Admin**: 任何工单
- **其他**: 仅自己相关的（否则403）

### GET /api/work-orders/statistics (工单统计)
- **Admin**: 统计所有工单
- **其他**: 统计自己相关的工单

### GET /api/work-orders/activities (活动日志)
- **Admin**: 所有活动
- **其他**: 仅自己相关工单的活动

## 💡 实际应用示例

### 场景1：区域经理发现问题，分配给店长处理
```
1. 区域经理创建工单
   - assignee_id = 店长ID
2. 店长在自己的工单列表中看到这个工单
3. 店长处理：待受理 → 进行中 → 已完成
4. 区域经理归档：已完成 → 已归档
```

### 场景2：店长需要外卖运营协助
```
1. 店长创建工单
   - assignee_id = 外卖运营ID
2. 外卖运营看到工单并处理
3. 外卖运营完成后更新状态
4. 店长确认后归档
```

### 场景3：外卖运营向区域经理反馈问题
```
1. 外卖运营创建工单
   - assignee_id = 区域经理ID
2. 区域经理看到工单
3. 区域经理处理并更新状态
4. 双方都可以查看处理进度
```

## 🔧 前端开发注意事项

### 1. 用户选择器
创建工单时的"受理人"选择器需要过滤：
```javascript
// ❌ 错误：显示所有用户
users.filter(u => u.role !== 'admin')

// ✅ 正确：排除admin
const availableAssignees = users.filter(u => u.role !== 'admin');
```

### 2. 工单表单
```javascript
// assignee_id改为必填
{
  title: { required: true },
  type_id: { required: true },
  priority_id: { required: true },
  assignee_id: { required: true },  // ⚠️ 新改为必填

```

```javascript

  currentUser.role === 'admin' ||
  workOrder.creator_id === currentUser.id ||
  workOrder.assignee_id === currentUser.id;
```

## 🐛 常见问题

### Q: 为什么区域经理看不到某个工单？
**A**: 检查该工单的创建者和受理人，如果都不是这个区域经理，那么他确实看不到。

### Q: 能不能让区域经理看所有门店的工单？
**A**: 新系统中不再基于门店管辖，而是基于分配关系。如果需要区域经理看到，请在创建工单时将其设为创建者或受理人。

### Q: shop_id字段还有用吗？
**A**: 仍然保留（兼容旧数据），但不再影响工单可见性。可以用于统计和筛选。

### Q: 为什么不能给admin分配工单？
**A**: Admin是系统管理角色，负责全局管理而不是执行具体任务。
