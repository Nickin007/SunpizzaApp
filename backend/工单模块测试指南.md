# 工单模块后端测试指南

## 📋 **功能清单**

### **已实现的 API 接口：**

| 接口 | 方法 | 路径 | 说明 |
|-----|------|-----|------|
| 获取工单列表 | GET | `/api/work-orders/` | 支持分页、筛选、权限过滤 |
| 获取工单详情 | GET | `/api/work-orders/{id}` | 包含评论和附件 |
| 创建工单 | POST | `/api/work-orders/` | 自动设置门店和受理人 |
| 更新工单 | PUT | `/api/work-orders/{id}` | 更新状态、进度等 |
| 添加评论 | POST | `/api/work-orders/{id}/comments` | 支持文本和附件 |
| 获取任务类型 | GET | `/api/work-orders/dict/types` | 字典数据 |
| 获取优先级 | GET | `/api/work-orders/dict/priorities` | 字典数据 |
| 获取状态 | GET | `/api/work-orders/dict/statuses` | 字典数据 |
| 获取统计数据 | GET | `/api/work-orders/stats` | 各状态工单数量 |
| 获取可分配用户 | GET | `/api/work-orders/assignable-users` | 用于分配工单 |

### **3. 手动测试（使用 Postman 或 curl）**

#### **3.1 登录获取 Token**

```bash
curl -X POST http://localhost:5000/api/users/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
```

**复制返回的 token，用于后续请求。**

---

#### **3.2 创建工单**

```bash
curl -X POST http://localhost:5000/api/work-orders/ \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN_HERE" \
  -d '{
    "title": "【设备报修】咖啡机故障",
    "description": "咖啡机显示 E01 错误代码",
    "type_id": 3,
    "priority_id": 2,
    "due_date": "2025-10-25T18:00:00Z"
  }'
```

## 📊 **前端对接说明**

### **前端需要实现的功能：**

1. **工单列表页面**
   - 调用 `GET /api/work-orders/?status_id={status_id}&page={page}`
   - 支持下拉刷新和上拉加载更多

2. **创建工单表单**
   - 先调用字典 API 获取类型和优先级选项

   - 调用 `GET /api/work-orders/{id}`

   - 调用 `POST /api/work-orders/{id}/comments`

5. **更新工单状态**
   - 调用 `PUT /api/work-orders/{id}`
   - 可更新 `status_id`, `completion_progress`, `completion_notes`

6. **首页统计**
   - 调用 `GET /api/work-orders/stats`
   - 显示各状态的工单数量

## 🐛 **常见问题**

### **问题 1：无法连接到数据库**

**原因：** `.env` 文件配置错误或 MySQL 未启动

**解决：**
```powershell
# 检查 MySQL 服务
Get-Service -Name MySQL*

# 如果未运行，启动 MySQL
Start-Service -Name MySQL80
```

---

### **问题 2：401 Unauthorized**

**原因：** Token 未传递或已过期

**解决：**
- 重新登录获取新 token
- 确保请求头包含 `Authorization: Bearer {token}`

---

### **问题 3：创建工单失败（400 错误）**

**原因：** 必填字段缺失或数据格式错误

**解决：**
- 检查请求体是否包含 `title`, `type_id`, `priority_id`
- 检查 `due_date` 格式是否为 ISO 8601（例如 `2025-10-25T18:00:00Z`）
