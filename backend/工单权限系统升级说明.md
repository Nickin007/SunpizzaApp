# 工单权限系统升级说明

## 📅 更新日期
2025年10月16日

## 🎯 升级目标
简化工单权限体系，去除门店绑定限制，实现基于分配的灵活协作模式。

---

## 🔄 核心变更

### 变更1：去除门店绑定限制
**旧逻辑**：
- 区域经理只能看管辖门店的工单
- 店长只能看自己门店的工单
- 工单必须关联门店

**新逻辑**：
- 工单可见性不再依赖门店管辖关系
- shop_id字段保留（兼容旧数据），但不再强制要求
- 基于"谁创建"和"分配给谁"来控制可见性

---

### 变更2：统一角色权限
**旧逻辑**：
- 区域经理：看管辖门店工单，无法修改状态
- 店长：看本店工单，只能"进行中→已完成"
- 外卖运营：角色不存在

**新逻辑**：
- 4个角色：admin / regional_manager / shop_manager / eleme_operator
- 除admin外，其他三个角色权限完全相同
- 所有人都可以修改工单状态和优先级

---

### 变更3：新增分配规则
**旧逻辑**：
- 分配规则不明确
- 可以给任何人分配工单

**新逻辑**：
- ✅ 管理员 → 可分配给：区域经理/店长/外卖运营
- ✅ 区域经理 → 可分配给：店长/外卖运营/区域经理
- ✅ 店长 → 可分配给：区域经理/外卖运营/店长
- ✅ 外卖运营 → 可分配给：区域经理/店长/外卖运营
- ❌ 任何人都不能给管理员分配工单

## 🔧 技术实现细节

### 核心过滤逻辑
```python
# 旧代码（复杂，基于门店）
if role == 'regional_manager':
    managed_shop_ids = [s.id for s in Shop.query.filter_by(regional_manager_id=user_id).all()]
    query = query.filter(WorkOrder.shop_id.in_(managed_shop_ids))

# 新代码（简单，基于分配）
if role != 'admin':
    query = query.filter(
        (WorkOrder.creator_id == user_id) |
        (WorkOrder.assignee_id == user_id)
    )
```

### 创建工单时的验证
```python
# 新增：受理人验证
assignee_user = User.query.get(assignee_id)
if not assignee_user:
    return error_response('受理人不存在', 400)
if assignee_user.role == 'admin':
    return error_response('不能给管理员分配工单', 400)
```

### 修改工单权限检查
```python
# 新增：修改前先检查权限
if current_user['role'] != 'admin':
    if work_order.creator_id != user_id and work_order.assignee_id != user_id:
        return error_response('无权修改该工单', 403)
```

1. **操作**：eleme_operator创建工单，assignee_id设为regional_manager

   - 两人都可以修改

## 📋 数据库兼容性

### shop_id字段处理
- **保留原因**：兼容旧数据，避免数据丢失
- **新建工单**：可选填，前端可以不传
- **旧工单**：保持原有shop_id不变
- **未来优化**：可考虑数据迁移后删除此字段

### 受影响的表
- ✅ `work_orders` - 权限逻辑变更，数据结构不变
- ✅ `users` - 新增eleme_operator角色支持
- ✅ `shops` - regional_manager_id字段不再用于工单权限判断

## ⚠️ 注意事项

### 1. 旧数据处理
- 现有工单的权限逻辑会自动切换
- 如果某个工单的assignee_id为空，只有创建者能看到
- 建议检查并修复assignee_id为空的工单

### 2. 前端适配
- 创建工单时，assignee_id改为必填
- shop_id可以改为可选
- 用户选择器需要过滤掉admin角色

- 确保所有外卖运营账号的role字段设为'eleme_operator'
